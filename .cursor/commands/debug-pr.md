# Debug Failing GitHub Pull Request

Fix issues in the current open, failing GitHub pull request using the root cause analysis (RCA) document. This command implements fixes based on the RCA findings from the `rca-pr` command.

## CRITICAL: Debug Process

**MANDATORY**:

1. **First run `rca-pr`** to perform root cause analysis and generate the RCA document
2. **Then run `debug-pr`** to implement fixes based on the RCA findings
3. Use the RCA document to guide all fixes - it contains the root cause and recommended solutions

## Prerequisites

**REQUIRED**: An RCA must exist before running this command. The RCA is generated by the `rca-pr` command and posted to one of these locations:

### RCA Document Locations

The `debug-pr` command searches for RCA documents in the following order:

1. **PR Comments** (Direct RCA document)
   - Comments with header "## 🔍 Root Cause Analysis"
   - Posted directly on the PR by `rca-pr` command

2. **PR Comments** (RCA Issue Links)
   - Comments containing "RCA documented in issue #X" or similar
   - Links to a GitHub issue containing the full RCA

3. **PR Body** (Issue References)
   - Issue references in PR description (e.g., "Related: #123")
   - Issues mentioned in the PR body

4. **GitHub Issues** (Linked to PR)
   - Issues with `rca` label that reference this PR in the body
   - Issues with `rca` label that mention this PR in the title

5. **GitHub Issues** (Mentioning PR)
   - Issues with `rca` label that contain "PR #X" in title or body

### Verification

The command verifies that found issues are actually RCA documents by checking:

- Issue has `rca` label, OR
- Issue body contains "Root Cause", "RCA", or "Root Cause Analysis"

If no RCA exists, run `rca-pr` first to perform root cause analysis.

## Initial Setup

### 1. Get PR Information and Load RCA

```bash
# Get current branch and PR number
gh pr view --json number,title,body,headRefName,baseRefName,state,isDraft

# Get PR number for commands
PR_NUMBER=$(gh pr view --json number --jq '.number')
BRANCH_NAME=$(gh pr view --json headRefName --jq '.headRefName')

# Get repository owner and name
REPO_OWNER=$(gh repo view --json owner --jq '.owner.login')
REPO_NAME=$(gh repo view --json name --jq '.name')

echo "🔍 Searching for RCA document for PR #${PR_NUMBER}..."

# Initialize variables
RCA_COMMENT=""
RCA_ISSUE_NUMBER=""
RCA_SOURCE=""

# Method 1: Search for RCA in PR comments (direct RCA comment with header)
echo "  → Checking PR comments for RCA header..."
RCA_COMMENT=$(gh pr view $PR_NUMBER --json comments --jq '.comments[] | select(.body | contains("🔍 Root Cause Analysis") or contains("## 🔍 Root Cause Analysis") or contains("Root Cause Analysis")) | .body' | head -1)

if [ -n "$RCA_COMMENT" ]; then
  echo "✅ Found RCA in PR comment (direct RCA document)"
  echo "$RCA_COMMENT" > /tmp/rca_content.md
  RCA_SOURCE="PR comment"
else
  # Method 2: Search for RCA issue link in PR comments
  echo "  → Checking PR comments for RCA issue links..."
  RCA_ISSUE_LINK=$(gh pr view $PR_NUMBER --json comments --jq '.comments[] | select(.body | contains("RCA documented in issue") or contains("RCA in issue") or contains("Root Cause Analysis in issue")) | .body' | grep -oE 'issue #[0-9]+|issues/[0-9]+' | head -1)

  if [ -n "$RCA_ISSUE_LINK" ]; then
    RCA_ISSUE_NUMBER=$(echo "$RCA_ISSUE_LINK" | grep -oE '[0-9]+' | head -1)
    echo "✅ Found RCA issue link in PR comment: #${RCA_ISSUE_NUMBER}"
  else
    # Method 3: Search for issues in PR body
    echo "  → Checking PR body for linked issues..."
    PR_BODY_ISSUES=$(gh pr view $PR_NUMBER --json body --jq '.body' | grep -oE 'issues/[0-9]+|issue #[0-9]+' | head -1)

    if [ -n "$PR_BODY_ISSUES" ]; then
      RCA_ISSUE_NUMBER=$(echo "$PR_BODY_ISSUES" | grep -oE '[0-9]+' | head -1)
      echo "✅ Found issue reference in PR body: #${RCA_ISSUE_NUMBER}"
    else
      # Method 4: Search for issues with "rca" label linked to this PR
      echo "  → Searching for issues with 'rca' label..."
      RCA_ISSUES=$(gh issue list --label "rca" --limit 10 --json number,body --jq ".[] | select(.body | contains(\"PR #${PR_NUMBER}\") or contains(\"pull request #${PR_NUMBER}\") or contains(\"PR ${PR_NUMBER}\")) | .number" | head -1)

      if [ -n "$RCA_ISSUES" ]; then
        RCA_ISSUE_NUMBER="$RCA_ISSUES"
        echo "✅ Found RCA issue with 'rca' label linked to PR: #${RCA_ISSUE_NUMBER}"
      else
        # Method 5: Search for issues with "rca" label that mention this PR number
        echo "  → Searching for 'rca' labeled issues mentioning PR #${PR_NUMBER}..."
        RCA_ISSUES=$(gh issue list --label "rca" --limit 20 --json number,title,body --jq ".[] | select(.title | contains(\"PR #${PR_NUMBER}\") or contains(\"PR ${PR_NUMBER}\")) | .number" | head -1)

        if [ -n "$RCA_ISSUES" ]; then
          RCA_ISSUE_NUMBER="$RCA_ISSUES"
          echo "✅ Found RCA issue with 'rca' label in title: #${RCA_ISSUE_NUMBER}"
        fi
      fi
    fi
  fi

  # If we found an issue number, load it
  if [ -n "$RCA_ISSUE_NUMBER" ]; then
    # Verify the issue has "rca" label or contains RCA content
    ISSUE_LABELS=$(gh issue view $RCA_ISSUE_NUMBER --json labels --jq '.labels[].name' | grep -i "rca" || echo "")
    ISSUE_BODY=$(gh issue view $RCA_ISSUE_NUMBER --json body --jq '.body')

    if [ -n "$ISSUE_LABELS" ] || echo "$ISSUE_BODY" | grep -qi "root cause\|RCA\|Root Cause Analysis"; then
      echo "✅ Loading RCA from issue #${RCA_ISSUE_NUMBER}"
      echo "$ISSUE_BODY" > /tmp/rca_content.md
      RCA_SOURCE="Issue #${RCA_ISSUE_NUMBER}"
    else
      echo "⚠️  Issue #${RCA_ISSUE_NUMBER} found but doesn't appear to be an RCA document"
      RCA_ISSUE_NUMBER=""
    fi
  fi
fi

# Final check: if no RCA found, exit with error
if [ -z "$RCA_COMMENT" ] && [ -z "$RCA_ISSUE_NUMBER" ]; then
  echo ""
  echo "❌ Error: No RCA document found for PR #${PR_NUMBER}"
  echo ""
  echo "Searched in:"
  echo "  - PR comments (for '🔍 Root Cause Analysis' header)"
  echo "  - PR comments (for 'RCA documented in issue' links)"
  echo "  - PR body (for issue references)"
  echo "  - Issues with 'rca' label (linked to this PR)"
  echo "  - Issues with 'rca' label (mentioning this PR)"
  echo ""
  echo "Please run 'rca-pr' command first to perform root cause analysis"
  exit 1
fi

echo ""
echo "📄 Loading RCA from: $RCA_SOURCE"
```

### 2. Review RCA Findings

**CRITICAL**: Read and understand the RCA findings before implementing fixes.

```bash
# Display RCA content
cat /tmp/rca_content.md

# Extract key information from RCA
echo "=== Root Cause ==="
grep -A 5 "PRIMARY ROOT CAUSE\|Root Cause" /tmp/rca_content.md | head -10

echo "=== Recommended Solutions ==="
grep -A 15 "Recommended Solution\|Recommended Solutions" /tmp/rca_content.md | head -20

echo "=== Files Requiring Changes ==="
grep -A 10 "Files Requiring Changes\|Files to Modify" /tmp/rca_content.md | head -15
```

### 3. Check Current CI/CD Status

```bash
# View all checks for the PR
gh pr checks

# View detailed check status with conclusions
gh pr view --json statusCheckRollup --jq '.statusCheckRollup[] | "\(.name): \(.status) - \(.conclusion // "pending")"'

# List all workflow runs for this PR
gh run list --branch "$BRANCH_NAME" --limit 10

# Get the latest failed run
FAILED_RUN=$(gh run list --branch "$BRANCH_NAME" --json databaseId,conclusion,status --jq '.[] | select(.conclusion == "failure" or .status == "in_progress") | .databaseId' | head -1)
```

### 3. View Workflow Run Details

```bash
# View specific workflow run
gh run view $FAILED_RUN

# View failed jobs only
gh run view $FAILED_RUN --json jobs --jq '.jobs[] | select(.conclusion == "failure") | "\(.name): \(.conclusion)"'

# View logs for failed job
gh run view $FAILED_RUN --log-failed

# View logs for specific job
gh run view $FAILED_RUN --job <job-id> --log
```

### 4. Identify Failing Jobs

```bash
# Get all failed jobs with details
gh run view $FAILED_RUN --json jobs --jq '.jobs[] | select(.conclusion == "failure") | {
  name: .name,
  conclusion: .conclusion,
  startedAt: .startedAt,
  completedAt: .completedAt,
  steps: [.steps[] | select(.conclusion == "failure") | {
    name: .name,
    conclusion: .conclusion,
    number: .number
  }]
}'
```

## Debugging Workflow

### Step 1: Review RCA Findings

**MANDATORY**: Before implementing fixes, review the RCA findings to understand:

- The root cause
- Recommended solutions
- Files that need changes
- Implementation approach

```bash
# Review RCA content
cat /tmp/rca_content.md
```

### Step 2: Implement Recommended Solution

Based on the RCA document, implement the recommended solution:

1. **Identify the solution** from the "Recommended Solutions" section
2. **Review files to change** from the "Files Requiring Changes" section
3. **Implement the fix** following the RCA guidance
4. **Test the fix locally** before committing

### Step 3: Reproduce and Test Locally

```bash
# Checkout the PR branch
gh pr checkout $PR_NUMBER

# Run the failing check locally
# Example for lint:
npm run lint

# Example for tests:
npm test

# Example for build:
npm run build
```

### Step 4: Implement the Fix

1. **Review RCA document** - Understand root cause and recommended solution
2. **Make necessary code changes** - Follow the RCA recommendations
3. **Test fix locally**:
   ```bash
   # Run the specific check that failed
   npm run lint          # If lint failed
   npm run type-check   # If type-check failed
   npm test             # If tests failed
   npm run build        # If build failed
   ```

### Step 5: Commit and Push Fix

```bash
# Stage changes
git add <fixed-files>

# Commit with proper message
git commit -m "fix(scope): resolve [specific issue from CI failure]"

# Push to update PR
git push origin $BRANCH_NAME
```

### Step 6: Verify Fix

```bash
# Wait for CI to run (or trigger manually)
gh workflow run <workflow-name> --ref $BRANCH_NAME

# Monitor the new run
gh run watch
```

## Debugging Checklist

- [ ] Identified which check/job is failing
- [ ] Viewed detailed error logs from GitHub Actions
- [ ] Reproduced the issue locally
- [ ] Identified root cause (not just symptoms)
- [ ] Fixed the issue
- [ ] Tested fix locally (all checks pass)
- [ ] Committed fix with proper message
- [ ] Pushed fix to PR branch
- [ ] Verified CI passes after fix
- [ ] Documented the issue and solution (if non-trivial)

## Best Practices

- **Reproduce locally first**: Don't guess - reproduce the exact failure
- **Read full error logs**: Don't just look at summary - read complete error messages
- **Check recent changes**: Review what changed in the PR that might have caused the failure
- **Test incrementally**: Fix one issue at a time, test, then move to next
- **Document findings**: If the issue is complex, document it for future reference
- **Use proper commit messages**: Follow Conventional Commits when fixing issues
- **Verify before pushing**: Always test locally before pushing fixes
